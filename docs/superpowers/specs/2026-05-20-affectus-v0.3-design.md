# affectus v0.3.0 設計書 — Raw Numeric Output（離散化レイヤーの撤廃）

- **作成日**: 2026-05-20
- **作者**: yokomachi
- **対象**: affectus v0.3.0（minor release、**breaking change**）
- **前提**: affectus v0.2.0

## 1. 背景・動機

v0.2 までの `affectus show` / `feel` のテキスト出力は、内部の連続値（float 0.0–1.0）を以下のステップで離散ラベル化していた：

1. `render.threshold` 未満の軸を捨てる
2. `render.max_axes` で上位3軸に絞る
3. `render.bands` で各値を 3 段階のラベルへ変換（「かすかな」「ほどほどの」「強い」）
4. `render.template` で日本語テンプレに流し込む

これは **「verbalization は LLM の仕事、affectus は判断を持たない決定論的コンポーネント」** という v0.1〜v0.2 設計書の中核原則に**矛盾している**。離散化と salience filtering（どの軸が "目立つ" か）は本質的に解釈的な決定であり、affectus が引き受けるべきではない。

eval 実験（feat/strands-eval ブランチ）でも、この離散化が予期せぬ非線形性を生み出していた可能性が指摘された：閾値を跨いだ瞬間に表現が一段強くなる step-function 的挙動が、LLM 応答の鋭敏化に寄与していた疑い。

v0.3 では原則に立ち返り、affectus が LLM に渡す情報を **「全軸の生の数値（JSON 1 行）」** のみに限定する。

## 2. 変更内容

### 2-1. `affectus show` / `feel` の出力フォーマット変更（breaking）

**Before（v0.2）:**
```
$ affectus show
いまはほどほどの喜び、ほどほどの信頼感とかすかな驚きを感じている。
```

**After（v0.3）:**
```
$ affectus show
{"joy":0.50,"trust":0.40,"fear":0.00,"surprise":0.20,"sadness":0.00,"disgust":0.00,"anger":0.00,"anticipation":0.00}
```

- **全軸を config 順で 1 行 JSON にシリアライズ**
- 値は小数点以下 2 桁固定（`%.2f`）
- 閾値・上位 N・離散ラベルは一切適用しない
- `feel` も `feel` 適用後の状態を同じフォーマットで返す

### 2-2. `render` config セクションの廃止

`Config` 構造体から `Render RenderConfig` フィールドを削除。`RenderConfig` 構造体と `Band` 構造体も削除する。デフォルト config・ja config から `render:` ブロックを除去する。

旧 config に `render:` セクションが残っていても **YAML パーサが無視する**だけで（go-yaml v3 のデフォルト挙動）、エラーにはしない。ユーザの破壊的影響は最小限。

### 2-3. `Render(s State, cfg Config) string` のシグネチャは維持

実装は刷新するが、関数シグネチャは変えない（呼び出し側 cli / mcp / viz への波及を最小化）。`cfg.Axes` の順序を使って JSON を組み立てる。

### 2-4. `affectus show --format json` の整理

v0.2 の `--format json` は `{"fragment": "...", "axes": {...}}` を返していた。v0.3 では `fragment` は axes JSON と実質同一になるので、`--format json` は `{"axes": {...}}` のみを返すように整理（pretty 印字、複数行）。

### 2-5. `examples/system-prompt-snippet.md` の改訂

LLM 向け指示を「数値 JSON を受け取って、Plutchik 関係構造を踏まえて自分で意味づけする」と明示する。「強い○○」「ほどほどの○○」のような言い回しは affectus からは来ないと注記。

### 2-6. その他の波及

- `internal/mcp/server.go` の `emotion_show` / `emotion_feel` ツール description を更新
- README の Quick start サンプルを v0.3 出力に差し替え
- 既存テスト（`render_test.go` 等）を v0.3 仕様に書き換え

## 3. スコープ外

- 内部 state（`state.json` のディスク表現）の変更：**しない**。version / updated_at / axes 構造はそのまま
- decay / apply / clamp 等の数値演算ロジック：**変更なし**
- viz のロジック：**変更なし**（viz は内部 state を直接読むので render 出力に依存しない）
- 軸の追加・削除・名前変更：**しない**
- リリース後の eval rig 再実行：**v0.3 リリース後の別作業**

## 7. リリースノート（草稿）

```
## v0.3.0 — Raw Numeric Output

**Breaking change**: `affectus show` and `affectus feel` no longer emit a
templated natural-language sentence. They now emit a one-line JSON object
of all axes in config order:

  $ affectus show
  {"joy":0.50,"trust":0.40,"fear":0.00,"surprise":0.20,"sadness":0.00,...}

### Why

The previous text rendering applied thresholds, salience filtering, and
band-label discretization — all interpretive decisions that, per affectus's
core design principle, belong to the LLM. v0.3 removes that layer: affectus
provides a snapshot of the emotion vector, and the LLM is responsible for
reading it relationally and modulating its response.

### Migration

- Custom configs may keep the obsolete `render:` block (it's silently
  ignored), or drop it for cleanliness.
- Agents wired to v0.2 outputs need a system-prompt update; see
  `examples/system-prompt-snippet.md` for the v0.3 guidance.

### Unchanged

- The on-disk state schema (`state.json` with `version`, `updated_at`, `axes`)
- Engine arithmetic (decay, apply, clamp, halflives)
- `affectus viz` behavior
```
