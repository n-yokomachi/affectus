# affectus v0.2.0 設計書 — リアルタイム可視化（viz）と関係的読解スニペット

- **作成日**: 2026-05-20
- **作者**: yokomachi
- **対象**: affectus v0.2.0
- **前提**: affectus v0.1.1（CLI ＋ 8軸感情ベクトル ＋ 二層ループ）

## 1. 概要・背景

affectus に2つの変更を入れる。

1. **`affectus viz` サブコマンド** — 感情ステートをローカルブラウザでリアルタイム可視化する GUI
2. **system-prompt スニペット改訂** — エージェント側 LLM が感情を「関係的に」読むための指示を追加

背景：affectus を題材にした技術記事の制作過程で、(a) 感情を Plutchik の関係構造（対極・隣接）として扱いたい、(b) 感情の動きを人目を引く形で見せたい、という要望が出た。

設計判断として確認済みの前提：

- 感情の **verbalization（意味づけ・命名）は LLM の仕事**。affectus は判断を持たない決定論的コンポーネントという原則を維持する。よって関係的読解はスニペット（プロンプト）側で行わせ、affectus のエンジン（decay/apply/render）は無改修とする。
- クオリア構造学・圏論は affectus に load-bearing な形では実装しない（数値実装の形になっておらず、affectus の「エンジンは dumb」原則とも噛み合わないため）。関係構造の実体は **Plutchik の感情の輪**であり、それを正直な基盤とする。

## 2. スコープ

### 2-1. 本設計に含む
- `affectus viz` サブコマンド（ローカル HTTP サーバ＋埋め込み GUI）
- `examples/system-prompt-snippet.md` の改訂
- デフォルト設定 `plutchik8.default.yaml` の `axes` 並べ替え（viz の円環配置のため。詳細は §3-6）

### 2-2. 非目標
- 感情エンジン（decay/apply/render/state）の改修 — 一切行わない
- 圏論・クオリア構造の数値実装、感情類似度行列
- viz による状態の書き換え（viz は読み取り専用）
- 認証・リモート公開（ローカルホスト限定）
- TTS・アバター等の表現チャネル拡張

## 3. 変更1: `affectus viz` サブコマンド

### 3-1. 動作・CLI

```
affectus viz [--port N] [--config P] [--state P]
```

- ローカル HTTP サーバを起動し、起動時にアクセス URL を標準出力へ表示する。
- デフォルトポートは `8765`。`--port` で変更可。
- `--config` / `--state` はグローバルフラグと同様に解決（既定 `~/.config/affectus/`、環境変数 `AFFECTUS_CONFIG` / `AFFECTUS_STATE` も従来どおり）。
- Ctrl-C（SIGINT）で停止。
- **読み取り専用**：ステートファイルを読むのみで書き込まない。よって状態ロックは不要（`SaveState` のアトミックな temp+rename により、読み取りは常に完全な旧版か新版のいずれかを見る）。
- 依存追加なし：Go 標準ライブラリ `net/http`、ページ資産は `go:embed`。

### 3-2. エンドポイント

| メソッド・パス | 返すもの |
|---|---|
| `GET /` | 埋め込み HTML（可視化ページ） |
| `GET /state` | 現在の感情ステート JSON（§3-3） |

`GET /state` のレスポンス例：

```json
{
  "updated_at": "2026-05-20T12:34:56+09:00",
  "clamp": { "min": 0.0, "max": 1.0 },
  "axes": [
    { "name": "joy", "value": 0.61 },
    { "name": "trust", "value": 0.42 }
  ]
}
```

- `axes` は **設定の `axes` リスト順**の配列（フロントは円環にこの順で等間隔配置する）。
- `value` は保存済みの生値ではなく、**`Decay` を通して「リクエスト時刻 now」まで減衰させた値**。
- `clamp` はバー長・色のスケール用（既定 0.0〜1.0）。

### 3-3. リアルタイム性（decay-to-now）

- フロントの HTML は `GET /state` を約1秒間隔でポーリングする。
- サーバは毎リクエストで `Decay(LoadState(...), cfg, time.Now())` を計算して返す。
- 結果：`feel` が走らないアイドル中も、ポーリングのたびに減衰が進み、**バーが時間とともに短くなる様子が見える**。`feel` でステートファイルが更新されると、次のポーリングで新値に切り替わる（ジャンプ）。
- affectus 既存の `engine.Decay` をそのまま再利用する（新規ロジックなし）。

### 3-4. 可視化（1ページ・2パネル）

フロントは素の HTML/CSS/JavaScript ＋ SVG。フレームワーク不使用。

**パネル1：感情の円環図**
- 8感情（設定の軸）を円周上に等間隔で扇形配置。
- 各扇形の色：軸の円環上の位置 `i` から色相 `hue = 360 * i / N` を自動割り当て。**強度 `value` を彩度／不透明度にマッピング**（低い＝淡い／透明、高い＝濃い／不透明）。設定への色フィールド追加は不要。
- 扇形の輪郭は常に表示し、全感情が低くても輪の形が分かるようにする。

**パネル2：減衰バー図**
- 各軸を横棒（または縦棒）で表示。**棒の長さ＝`value`**（`clamp` でスケール）。
- 8軸すべてを安定したレイアウトで表示（低い軸は短い棒）。
- §3-3 のポーリングにより、時間経過とともに棒が短くなる＝減衰が可視化される。

### 3-5. ファイル構成

```
affectus/
├── cmd/affectus/
│   ├── main.go            # dispatch に "viz" ケースを追加
│   └── viz.go             # runViz: viz.Serve を呼ぶ薄いラッパ
└── internal/viz/
    ├── server.go          # HTTP サーバ、/ と /state ハンドラ
    ├── server_test.go     # httptest によるハンドラ検証
    └── assets/
        └── index.html     # 埋め込む可視化ページ（CSS/JS インライン）
```

- `internal/viz` は `internal/engine`（`LoadConfig`/`DefaultConfig`/`LoadState`/`Decay`/`Config`/`State`）を再利用する。
- `index.html` を `go:embed` でバイナリに同梱。

### 3-6. 設定への影響

デフォルト設定 `internal/engine/plutchik8.default.yaml` の `axes` リストを **Plutchik の輪の円環順**に並べ替える：

```
joy → trust → fear → surprise → sadness → disgust → anger → anticipation
```

（現状は対極ペア順 joy,sadness,trust,disgust,… で並んでいる。）

- 理由：viz は「設定リスト順＝円環の配置順」とするため。輪の順に並べると、対極ペアが円の正反対に配置される。
- **エンジン動作に軸順は影響しない**（decay/apply は独立、render は値でソート、state は map）。よって機能的に無害。
- 値・半減期・対極・render 設定は変更しない。並べ替えのみ。

## 4. 変更2: system-prompt スニペット改訂

`examples/system-prompt-snippet.md` に、感情を関係的に読むための節を追加する。趣旨：

- 8つの感情軸は Plutchik の輪の関係構造を持つ（対極ペア4組、隣接関係）。
- **隣接する感情が同時に立っている**ときは、混ざり合った一つの豊かな感情として読む（例：喜び＋信頼 → 親愛の方向）。
- **対極の感情が同時に立っている**ときは、葛藤・複雑な心境として読む（例：喜び＋悲しみ → ほろ苦さ）。
- 感情を軸ごとに分解せず、関係として読み取り、応答のトーンに反映する。
- 創発する感情の命名（「愛おしさ」等）は LLM が行う。affectus は構造と読み方を渡すだけ。

対極ペアと隣接ペアの一覧をスニペット内に明記する。affectus 本体（config・エンジン）は改修しない。

## 5. エラー処理

| 事象 | 挙動 |
|---|---|
| ステートファイル無し | `LoadState` がベースラインを返す（既存挙動）。viz はベースライン状態を表示 |
| 設定ファイル無し | 埋め込みデフォルト設定を使用（既存挙動） |
| ポート使用中 | エラーを表示して終了 |
| `feel` 等との同時アクセス | viz は読み取りのみ。`SaveState` のアトミック書き込みにより torn read は起きない。ロック不要 |

## 6. テスト

- `internal/viz/server_test.go`：`httptest` で HTTP ハンドラを検証。
  - `GET /state` が decay 済みの値を返す（`updated_at` から時間を進めた状態で値が減衰している）
  - `GET /state` の `axes` が設定のリスト順である
  - `GET /` が HTML を返す
  - ステートファイル欠損時にベースラインを返す
- フロントエンド JavaScript は手動スモークテスト（ブラウザで円環図・減衰バーの描画とポーリング更新を確認）。
- スニペットはドキュメントのためテストなし。
- 既存テスト（engine / cli / mcp / cmd）はすべてパスを維持。
